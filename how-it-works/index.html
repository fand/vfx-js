How it Works

VFX-JS draws your elements with WebGL, on one canvas over the page. When you call vfx.add(el):

  1. Capture. VFX-JS copies the element into a WebGL texture.
  2. Hide. It sets the element's opacity to 0. The element keeps its box in the layout.
  3. Track. Every frame, it reads the element's position and size.
  4. Draw. It runs the shader in that box, on one canvas over the page.

The DOM stays DOM

  • new VFX() adds one <canvas> to <body>, or to the wrapper you pass. It has pointer-events: none and z-index: 9999 by default.
  • The element stays where it is. Only its opacity changes. A video gets 0.0001, not 0, to avoid jank frames. addHTML wraps the element in a canvas instead.
  • Clicks, links, text selection, focus and screen readers still use the real element. CSS layout and animations still move it, and the effect follows.

Element capture

Each element type becomes a texture in its own way. This decides when you need vfx.update(el).

Element How it is captured After a change
<img> Loaded once, after the image loads. A .gif URL plays frame by frame. Call update(img) after you change src.
<video> Read again every frame. VFX-JS waits for canplay first. Nothing to do.
<canvas> Copied once, when added. Call update(canvas) after you draw.
Text and other elements Drawn to an image through SVG <foreignObject>, once. Call update(el) after the content changes. A window resize that changes its size captures it again.
addHTML(el) html-in-canvas. The browser paints the element into a canvas each time it changes. Live. Falls back to the text path where not supported.
  • html-in-canvas is a new browser API. Today it works only in Chrome behind chrome://flags/#canvas-draw-element. addHTML logs a warning and uses the text path where it is missing.
  • addHTML wraps the element in a <canvas>. The element must fill its parent's width or have a fixed px width.
  • Images and videos from another origin need CORS, or WebGL cannot read them.

Overflow

A shader draws only inside the element's box. To draw outside it, for glow or glitch, give it more room.

  • With a shader, set overflow. In the extra area, uv goes below 0 and above 1.
  • The texture has nothing outside the element, but wrap defaults to "repeat". Check uv before you read src there, or set wrap: "clamp".
  • Effects ignore overflow. Each effect sets its own room with outputRect. In an effect, uvContent is 0..1 over the element, and the rest is padding.

Code that reads the extra area is in Custom Shaders and Custom Effects.

Scroll and visibility

  • Every frame, VFX-JS checks each element's box, plus its overflow, against the viewport. Elements out of view are skipped. They cost no GPU time.
  • The canvas is a bit bigger than the viewport (10% on each side by default) and moves with the page. So fast scrolling does not show a gap. Set scrollPadding to change it, or false for a fixed canvas.
  • The intersection option sets when the element counts as "in view": threshold (0 to 1) and rootMargin, like IntersectionObserver. leaveThreshold sets when it leaves (default: threshold). duration sets the enter and leave time in seconds (default: 1).
  • The visible ratio divides by the smaller of the element size and the viewport size, on each axis. So an element taller than the viewport can still reach 1.
  • This drives the intersection, enterProgress, leaveProgress, enterTime and leaveTime uniforms.

Uniforms and timing

VFX-JS sets these uniforms for each element. Declare only the ones you use.

Uniform Meaning
sampler2D src The element texture.
vec2 resolution Element size in physical px.
vec2 offset Element origin in the render target, physical px.
vec4 viewport Render target rect (x, y, w, h) in physical px.
float time Seconds since the element was added.
vec2 mouse Mouse position in render target px, same space as gl_FragCoord.
float intersection How much of the element is in the viewport, 0 to 1.
float enterTime Seconds since the element entered the viewport.
float leaveTime Seconds since the element left the viewport.
float enterProgress Enter transition, 0 to 1. Plays backward if the element leaves mid-way.
float leaveProgress Leave transition, 0 to 1. Stays 0 until enter finishes.
bool autoCrop The autoCrop option. Default true.
sampler2D backbuffer The previous frame. Needs backbuffer: true.
  • uv = (gl_FragCoord.xy - offset) / resolution gives element space: (0, 0) is bottom-left, (1, 1) is top-right.
  • Use enterProgress and leaveProgress for enter and leave animations. They turn back smoothly when the user scrolls back mid-way. Use enterTime and leaveTime for animations timed in seconds.
  • Your own uniforms can be functions. They run every frame, only while the element is drawn.
  • Effects get the same values on ctx: ctx.time, ctx.deltaTime, ctx.mouse, ctx.intersection, ctx.enterProgress, ctx.leaveProgress, ctx.enterTime, ctx.leaveTime.

time comes from the VFX clock, not the wall clock. You can pause it, slow it down, or pin it for stable screenshots.

Limits

  • Browser only, and WebGL is required. new VFX() throws without it. VFX.init() returns null instead. Either way the page stays plain HTML.
  • With prefers-reduced-motion: reduce, VFX-JS draws nothing. Elements stay plain HTML, and transitions cut. It is checked once, when VFX is created.
  • All effects draw on one canvas, at one z-index. Page content cannot sit between two effects. Use the zIndex option to order effects inside the canvas.
  • The canvas does not know about CSS clipping. An element hidden by a parent's overflow: hidden or a scroll box is still drawn.
  • VFX-JS owns the element's inline opacity while it is added. Use overlay instead of setting it yourself.
  • Text, other elements and <canvas> are snapshots. Call vfx.update(el) after they change.
  • Each VFX has its own WebGL context. Make one per page and reuse it.
  • shader and effect can't be used together. Make a new Effect instance for each element.
